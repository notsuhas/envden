title: Push, pull and resolve conflicts
description: Sync a repo, inspect changes and resolve a file that changed on two devices.
---

## Sync your current repo

Inside a tracked checkout, run:

```sh
envden pull
# edit your env files
envden diff
envden push
```

`diff` reports key names and change markers without values. `push` and `pull` print JSON results. For example, a push that uploads one file without local reconciliation changes prints:

```json
{ "kind": "pushed", "changed": 1, "conflicts": 0 }
```

Add `--all` to sync every tracked repo. A push commits its changes in one manifest swap. If another device pushes first, envden retries against the new state. If the head keeps moving, it asks you to retry.

```sh
envden pull --all
envden push --all
```

Pull merges unpushed edits rather than replacing them. Before overwriting a file, envden saves a backup under `~/.envden/conflicts/`. Backups expire after 30 days.

## Choose which files to sync

By default, envden discovers `.env` and `.env.<name>`, excluding `.example`, `.sample`, `.template` and `.defaults` templates. It never syncs `.envrc` or git-tracked files. Discovery selects gitignored files and skips build folders such as `node_modules`, `.next`, `dist` and `build`. The maximum file size is 1 MiB.

To change discovery rules:

```sh
envden config env-files '{"include":[".env",".env.*"],"exclude":["*.example","*.sample","*.template","*.defaults"],"extraSkipped":["generated"]}'
```

This replaces the include and exclude patterns and adds skipped directory names. Patterns without `/` match basenames; patterns with `/` match paths relative to the checkout. Tracked files and `.envrc` remain excluded.

## Review a merge

A merge compares the raw bytes of each key's assignment, including its comments. Your local file supplies the layout. New remote keys go at the end in remote order.

Changes to different keys can merge cleanly. envden shows key names and asks you to confirm. `--yes` accepts clean changes and is required for a push without a terminal. It doesn't resolve conflicts.

A file becomes a conflict when both sides change the same key, or one deletes a key the other edits. Duplicate keys, unterminated quotes, multiline values, changes to `export` or quoting, and a comment toggle against an edit also need manual resolution.

## Resolve a conflict

A push or pull with unresolved conflicts exits with code **3**. List them first:

```sh
envden resolve --list
```

The JSON array includes each conflict's checkout `root`, relative `path`, editable `file`, and saved `mine` and `server` paths. With no conflicts, it prints `[]`.

Choose a version for one file:

```sh
envden resolve .env --repo /path/to/checkout --keep-mine
envden resolve .env --repo /path/to/checkout --take-server
```

To combine the versions yourself, edit the `file` path from `--list`, then run:

```sh
envden resolve .env --repo /path/to/checkout
```

A successful resolution prints:

```json
{ "kind": "resolved", "path": ".env" }
```

The command must select exactly one conflict. Resolution updates the local file; run `envden push` to publish it.

## Check status and install the shell notice

```sh
envden status
envden status --json
envden shell install zsh
```

The shell notice supports `zsh`, `bash`, `fish` and `powershell`. It checks a cache on shell start and `cd`, then prints a line when the checkout is out of sync. A stale cache triggers a background refresh after 60 seconds. The hook doesn't run git or write checkout files, and it doesn't push or pull.

To remove it:

```sh
envden shell uninstall zsh
```

## History and restore

The server keeps every version for 90 days and at least the last 20 versions of each file. To see them:

```sh
envden history            # env files in this checkout
envden history .env       # one file, including a deleted one
envden history --all      # every tracked file
```

```
github.com/you/app .env
  v3  2026-11-14 18:02  laptop            changed TOKEN  <- current
  v2  2026-11-12 09:40  desktop           added DB_URL
  v1  2026-11-01 11:15  laptop            added TOKEN
```

Each version shows when it was pushed, which device pushed it ("removed device" if it has since left the vault) and the key names that changed since the version before. Values never appear. Deletions show as `deleted`, and server repairs as `restored` or `lost`. `<- current` marks the version this checkout matches. When the server has pruned older versions, the list ends with `older versions pruned`. `--json` prints the same data for scripts.

To go back to an old version:

```sh
envden history .env --restore 1
envden diff
envden push
```

Restore writes that version into your file as an ordinary local edit, backs up the old content under `~/.envden/conflicts/backups`, and prints the key names it changed. Nothing reaches other devices until you push. In link mode it writes the store file the link points to, so every linked checkout of the repo sees it. Local-only, detached and conflicted files are refused. Restore asks first in a terminal; `--yes` skips the question. Without a terminal it needs `--yes` and `envden config agent-merge on`, so an agent can't restore on its own.

Deletion records survive pruning, so a device returning from offline can't bring a deleted file back without an explicit restore.

## Delete an env file everywhere

```sh
envden rm /path/to/checkout/.env
envden push --yes
```

`rm` asks before discarding local edits or conflicts, backs up every local version, and removes the file from all local targets and the store. The next push publishes the deletion. Other devices remove the file on pull, or conflict if they have edits. Missing files alone are restored.

Use `--yes` to confirm without a terminal and `--json` for the result and backup paths. Success exits 0; refusal or cancellation exits 2; an unknown tracked path or an I/O failure exits 1. To add it again after publishing deletion, create the file and track the checkout again.

A lost push response is checked against the verified history, even if another device has since pushed again. Retrying a partial pull fast-forwards superseded server bytes. Deliberate local reverts still push.

`rm` records deletion only after removing local files. Recreating a target cancels pending removal. Resolving to live content also clears removal intent. A changed server entry requires another confirmation; unpublished files are removed locally without a tombstone. Checkouts needing approval are skipped. Backup reports include the source and saved path.

Push reports held-back files with a reason and next action, including conflicts, placement failures and `env-files` exclusions. `status` checks current approvals, rules, conflicts and placement state. JSON includes these reports.

Untracking cancels a pending removal and prints `Cancelled removal: <path>`. Track the checkout again to receive the server's file.

A regular file replacing a tracked symlink is a user edit, including a revert. Envden adopts it when the store is unchanged; different unpushed edits in both places produce one conflict.

Corrupt per-file sync records are moved to a named backup and reported by `status`. Run `pull`, then `resolve --list` to choose the content. If the error names `applied-files.json`, back up local env files, move that file aside, then run `pull` and resolve conflicts before pushing.
