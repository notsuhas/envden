## 1. Run the server

Create a Tailscale auth key for the server. On your Docker host, run:

```sh
docker run -d --name envden --restart unless-stopped \
  --read-only --cap-drop ALL --security-opt no-new-privileges:true \
  --tmpfs /tmp:uid=10001,gid=10001,mode=1777 \
  --tmpfs /var/run/tailscale:uid=10001,gid=10001,mode=0700 \
  -e TS_AUTHKEY="tskey-auth-..." \
  -v envden-data:/data \
  -v tailscale-state:/var/lib/tailscale \
  ghcr.io/notsuhas/envden:0
```

Replace `tskey-auth-...` with your auth key. The volumes keep envden data and Tailscale state across container replacements. The key is needed only for first login or reauthentication. The container joins your tailnet as `envden`; set `TS_HOSTNAME` to choose another name.

The container uses userspace Tailscale. You don't need privileged mode, a TUN device or a published host port. `tailscale serve` exposes the localhost server over HTTPS.

Read the setup token:

```sh
docker logs envden
```

The token is the single word printed under the `Setup token` line. Keep it for the next step. It lets your laptop check that it reached this server before creating a vault. The server prints it only on first start, and it's used up when a vault is created.

## 2. Set up your first device

[Install the CLI](/docs/getting-started) on your laptop. Use the server's full Tailscale HTTPS address:

```sh
envden setup --server https://envden.your-tailnet.ts.net
```

Replace the example hostname with yours. In your terminal, enter the setup token (piping it cannot complete the secret prompts), accept or edit the device name (your hostname without its domain) and choose a master password.

Setup prints a recovery kit before it creates the vault. Store it somewhere you can recover without this laptop. You can write it directly to a private file with `--kit-out /path/to/kit.json`. A kit with the master password written on it gives full access to the vault.

Setup also asks about telemetry, update checks, the shell notice and the agent skill. It scans your home folder for repos, asks you to approve checkouts, places their env files and pushes them.

If setup stops partway, run it again. It asks whether you still have the kit it printed; if you don't, it finishes creating the vault and prints a replacement kit.

To scan a smaller folder:

```sh
envden setup --server https://envden.your-tailnet.ts.net --scan-root ~/Work
```

Each clone needs approval, and `--yes` doesn't skip it. Worktrees you add later to an approved clone are approved on their first sync. macOS may ask for folder access during the scan.
