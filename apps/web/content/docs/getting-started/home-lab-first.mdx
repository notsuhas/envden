## 1. Run the server

Create a Tailscale auth key for the server. On your Docker host, run:

```sh
docker run -d --name envden --restart unless-stopped \
  --read-only --cap-drop ALL --security-opt no-new-privileges:true \
  --tmpfs /tmp:uid=10001,gid=10001,mode=1777 \
  --tmpfs /var/run/tailscale:uid=10001,gid=10001,mode=0700 \
  -e TS_AUTHKEY="tskey-auth-..." \
  -v envden-data:/data \
  -v tailscale-state:/var/lib/tailscale \
  ghcr.io/notsuhas/envden:0
```

Replace `tskey-auth-...` with your auth key. The volumes keep envden data and Tailscale state across container replacements. The key is needed only for first login or reauthentication. The container joins your tailnet as `envden`; set `TS_HOSTNAME` to choose another name.

The container uses userspace Tailscale. You don't need privileged mode, a TUN device or a published host port. `tailscale serve` exposes the localhost server over HTTPS.

Read the setup token:

```sh
docker logs envden
```

The token is the single word printed under the `Setup token` line. Keep it for the next step. It lets your laptop check that it reached this server before creating a vault. The server prints it only on first start, and it's used up when a vault is created.

## 2. Set up your first device

[Install the CLI](/docs/getting-started) on your laptop. Use the server's full Tailscale HTTPS address:

```sh
envden setup --server https://envden.your-tailnet.ts.net
```

Replace the example hostname with yours. Enter the setup token, then accept or edit the device name (your hostname without its domain). That's all setup asks before it creates the vault.

Setup then shows your recovery code once:

```text
  Recovery code:  ER1-7KQ2M-X9D4F-…

Store this in your password manager. It's the only way back in if you lose every device.
```

Save it in your password manager and confirm. envden never stores it. For scripts, `--recovery-code-out /path/to/code.txt` writes it to a new private file instead of showing it.

Setup also asks about telemetry, update checks, the shell notice (a line in your terminal when you `cd` into a checkout that needs a push or pull) and the agent skill (instructions that let AI coding agents run envden safely). Each has a default you can take with Enter; pick No for anything you don't want.

Then it scans your home folder for repos and lists each checkout with the env files it found, all selected. Press Enter to sync them, or Space to leave one out. Setup places their env files, pushes them and ends with a summary of the vault, this device and what it tracks. If you leave everything out, add checkouts later with `envden track`.

If setup stops partway, run it again. It finishes creating the vault and shows a new recovery code, since you may not have seen the first one.

To scan a smaller folder:

```sh
envden setup --server https://envden.your-tailnet.ts.net --scan-root ~/Work
```

Each clone needs approval, and `--yes` doesn't skip it. Worktrees you add later to an approved clone are approved on their first sync. macOS may ask for folder access during the scan.

The scan skips hidden and dependency folders, and prints one line for repos it skipped; `--verbose` lists them. See [what the scan looks at](/docs/placement#track-a-checkout).
