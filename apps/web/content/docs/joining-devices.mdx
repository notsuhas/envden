---
title: Join and manage devices
description: Pair a machine, rename it or remove one you no longer use.
---

## Pair a new device

On a device already in the vault, run:

```sh
envden device add
```

Enter your master password. envden shows a single-use code such as `3-K7QF-2MXP`, valid for 10 minutes. Keep this terminal open.

On the new device, run:

```sh
envden join https://envden.your-tailnet.ts.net
```

Use your server's address and enter the pairing code. envden suggests your hostname without its domain as the device name; edit it at the prompt or pass `--name`. Without a terminal it takes the suggestion. If another device already has that name, envden adds `-2`, `-3` and so on. On the existing device, confirm the new device's name. The new device checks that it reached the same server your other device uses, and stays unlocked for as long as that device has left.

On a machine without a desktop keychain, such as a server you reach over SSH, see [where device keys are kept](/docs/security#where-device-keys-are-kept) before joining.

If the join stops after the code was accepted, run `envden join <server> --resume` to finish it. The approval stays on the server for 24 hours. If there's nothing to resume, `--resume` stops at once; start again with a new code.

## Join with your recovery kit

If another device isn't available, use your master password and kit:

```sh
envden join https://envden.your-tailnet.ts.net --recovery-kit /path/to/kit.json
```

Or use `--recovery` to enter the recovery secret key and vault ID yourself. Other devices report the recovery-kit join on their next command.

## Approve checkouts on the new machine

Every clone needs approval on this machine. A worktree of an approved clone is approved on its first sync; see [Placement](/docs/placement#track-a-checkout). If a local env file differs from the vault, choose whether to keep yours, take the server version or merge.

If Windows can't create symlinks, envden asks for consent before using copies.

## Unlock a device

A device needs your master password once per unlock period, 30 days by default. Run `envden unlock` when pushes and pulls stop. See [Manage the vault](/docs/vault#unlock-a-device) for the period and its limits.

## Rename this device

```sh
envden device rename work-laptop
```

This renames the device you run it on; no other device can rename it. If another device already has the name, the command fails; pick another. It needs no password while the device is unlocked, and every device lists the new name.

## Remove a device

List devices, then pass the device name or ID to `rm`:

```sh
envden device ls
envden device rm old-laptop
```

The list includes the envden version each device last used. Removal asks for your password, reports the file and key names the device could read, and asks for confirmation. Later pushes use a new encryption key that the removed device never gets. Success prints `Device removed`.

Rotate the exposed credentials at their providers. Removing a device cannot erase files or keys it already has. Use `--new-kit` to replace the recovery kit in the same removal.

## Manage vault keys and recovery

Rotating keys, replacing the recovery kit and changing or resetting the master password are on [Manage the vault](/docs/vault).
