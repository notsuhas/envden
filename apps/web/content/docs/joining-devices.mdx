title: Join and manage devices
description: Add a machine by comparing words, rename it or remove one you no longer use.
---

## Add a new device

On the new device, run:

```sh
envden join https://envden.your-tailnet.ts.net
```

Use your server's address. envden suggests your hostname without its domain as the device name; edit it at the prompt or pass `--name`. Then it waits for approval. Nothing else is typed.

On a device already in the vault, run:

```sh
envden device approve
```

You don't need to remember this: commands on that device, and the shell line, say `a device is waiting to join` while a request is open. If several devices are waiting, pick one, or pass the number shown.

Both screens then show the same three words, such as `tiger lamp river`. The approving device asks:

```text
laptop wants to join. Words: tiger lamp river. Do they match the other screen? (y/N)
```

The new device asks whether its words match too. Answer yes on both only if the words are the same. If another device already has the name, envden adds `-2`, `-3` and so on. A request expires after 10 minutes, and a no on either screen cancels it.

The words are how envden knows the device you're adding is the one on your other screen. Someone else on your network, or a tampered server, gets one guess per attempt, and its words match yours about once in eight billion tries. If the words differ, answer no.

If the new device stops after you confirmed, run `envden join <server> --resume` to finish. The approval stays on the server for 24 hours.

## Join with your recovery code

If every device is lost, use the recovery code that setup showed you:

```sh
envden join https://envden.your-tailnet.ts.net --recovery
```

Enter the device name and the code. envden checks the code for typos before it sends anything. Other devices report the recovery join on their next command. Remove your lost devices afterwards, as below.

## Approve checkouts on the new machine

Every clone needs approval on this machine. A worktree of an approved clone is approved on its first sync; see [Placement](/docs/placement#track-a-checkout). If a local env file differs from the vault, choose whether to keep yours, take the server version or merge.

If the filesystem can't create symlinks, envden asks for consent before using copies.

## Rename this device

```sh
envden device rename work-laptop
```

This renames the device you run it on; no other device can rename it. If another device already has the name, the command fails; pick another. Every device lists the new name.

## Remove a device

List devices, then pass the device name or ID to `rm`:

```sh
envden device ls
envden device rm old-laptop
```

The list marks this device with `*` and shows the envden version each device last used:

```text
* mainbook  this device · v0.4.0 · has held the recovery keys
  laptop-b  v0.4.0
  old-mac   not confirmed yet
```

Add `--verbose` for device IDs or `--json` for the raw data.

Removal reports the file and key names the device could read and asks for confirmation. Later pushes use a new encryption key that the removed device never gets. Success prints `Device removed`.

A lost or stolen device keeps syncing until you remove it, so remove it from another device as soon as you can. Rotate the exposed credentials at their providers: removing a device can't erase files or keys it already has. Use `--new-code` to replace the recovery code in the same removal; envden offers it when the removed device ever held the recovery keys.
