## What protects the vault

Each device has its own keys, and the server holds only ciphertext. The recovery code is the way back in if you lose every device. No device stores it. [Security](/docs/security) covers what each piece protects against.

| Task                      | Command                      | Needs                                 |
| ------------------------- | ---------------------------- | ------------------------------------- |
| Replace the recovery code | `envden vault recovery-code` | A device in the vault                 |
| Rotate keys               | `envden vault rotate`        | A device in the vault                 |
| Add a device              | `envden device approve`      | A device in the vault and the new one |
| Remove a device           | `envden device rm <device>`  | Another device in the vault           |

There are no passwords and no logins: a device in the vault signs each change with its own keys, and the server checks that it's still a member.

## Replace the recovery code

If the code may have leaked, or you lost it while you still have a device:

```sh
envden vault recovery-code
```

envden makes new recovery keys and a new code, switches to a new encryption key, and shows the code once. Store it in your password manager and confirm. The old code stops working. Without a terminal, pass `--recovery-code-out <file>` to write it to a new private file instead.

`envden device rm --new-code` replaces the code in the same step as a removal. envden offers this when the removed device ever held the recovery keys.

### If replacement is interrupted

envden shows the new code before it sends the change, and keeps the pending change on this device. If the command fails after showing the code, run it again:

- If the change reached the server, the rerun finishes it and prints `Finished an interrupted replacement; the code it showed is now the one that works`. To get another code, run the command once more.
- If it didn't, the code you were shown never took effect. The rerun makes and shows a fresh one; keep that and discard the other.

An interrupted `device rm --new-code` works the same way.

## Rotate keys

```sh
envden vault rotate
```

envden switches to a new encryption key for new writes. Existing files aren't re-encrypted. Success prints `Vault re-keyed; removed devices can't read new changes`. Offline devices get the new key on their next pull.

Removing a device already rotates. See [remove a device](/docs/joining-devices#remove-a-device).
