What it is: envden syncs env files over Tailscale with end-to-end encryption. The TypeScript implementation (packages/core, packages/adapters/*, apps/cli, apps/server; skip apps/web) is the reference. go/ is a port that must be indistinguishable from it: same stdout/stderr text, exit codes, files written (bytes, names, permissions), server DB rows and wire bytes, bugs included. docs/PROTOCOL.md is the source of truth for crypto and wire formats; docs/DESIGN.md for behaviour. CLAUDE.md has the code rules (they apply to Go in Go idiom). docs/ports/go.md and docs/ports/go-cli-layout.md map Go packages to TS files. PARITY-NOTES.md lists differences already known and accepted (don't re-report those unless you think the stated reasoning is wrong).

Your job: find real defects in the Go code, by reading Go side by side with the TS it ports, and by running things. Categories:
1. SECURITY: crypto misuse or deviation from PROTOCOL.md (key/signature/MAC/KDF/HPKE/OPAQUE/Argon2 parameters, labels, validation of keys, canonical encodings, strict decoders, constant-time comparisons, nonce/replay handling, rate limits, authorization of every server route and swap op, unlock/fresh windows, path traversal and symlink safety in placement and store, file permissions, secrets leaking into errors/logs/output, trusted-process execution, the local dashboard's token/Host/Origin checks, TOCTOU).
2. CORRECTNESS: logic that differs from TS in any input, including error paths, edge cases, concurrency (Go goroutines/mutexes vs Bun's single thread), integer overflow/width (bigint vs uint64, JS number precision), Unicode (UTF-16 length vs bytes, NFC/NFKC), JSON encoding (key order, escaping, number formatting), time handling.
3. PARITY: anything observable that would differ from TS: output text, exit codes, JSON, files, modes, DB rows, HTTP status/headers/bodies.
