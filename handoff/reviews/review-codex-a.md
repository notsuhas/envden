# codex-a findings

## 1. High | correctness / parity / security availability | Ed25519 verification rejects chains accepted by TypeScript

Go: `go/core/protocol/crypto/sign.go:30`
TS: `packages/core/src/protocol/crypto/sign.ts:24`

Go's `crypto/ed25519.Verify` checks the unmultiplied verification equation. The pinned Noble implementation used by TS checks the cofactored equation, including with `zip215: false`. Canonical encodings and rejection of small-order public keys do not make these equations equivalent. Go therefore rejects some signatures and signed device chains that TS accepts under the current protocol.

Reproduced using an ordinary public key from the synthetic seed `07` repeated 32 times. Let R be the canonical order-two point, encoded `ec` + `ff` repeated 30 times + `7f`. Compute S = H(R || A || framed_message) * a mod L, where a is that seed's usual expanded signing scalar. TS `Verify` returns `{ok:true,value:true}`; Go returns `{OK:false,Reason:"Invalid signature"}`. The public key is an ordinary prime-order key, R is canonical, and S is below L.

I also encoded a complete genesis entry with valid device/recovery records and this signature. Both implementations decode the same bytes. TS `verifyChain` returns `valid`; Go `devices.VerifyChain` returns `invalid` with no error. Evidence and executable repros:

- `/tmp/codex-a/ed.ts`, `/tmp/codex-a/ed.go`, `/tmp/codex-a/ed.json`: direct signature comparison.
- `/tmp/codex-a/genesis.ts`, `/tmp/codex-a/genesis.go`, `/tmp/codex-a/genesis.bin`: complete signed-chain comparison.

Run `bun /tmp/codex-a/genesis.ts`, then from `go/`, run `go run /tmp/codex-a/genesis.go`. The scripts import this checkout and use only synthetic keys and scratch files.

Impact: a signer can publish an otherwise valid TS chain entry using this signature construction. Go clients cannot accept that chain. Moving a TS database containing such an entry to the Go server also makes stored-chain validation fail, and membership verification subsequently fails for every member of that vault. This is a cryptographic acceptance split, not an unsigned-request bypass. Ordinary signatures generated by the standard signer do not trigger it.

Fix direction: match Noble's cofactored verification equation while retaining the existing strict public-key/point encoding checks and S < L requirement. Add this signed genesis and mixed-order cases as shared verification vectors. Do not change TS acceptance only in the Go-port PR.
